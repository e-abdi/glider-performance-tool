# Data behind the Endurance calculation page

## `extra-sensors.csv` — add a sensor here

The external payload on the [Endurance calculation](../slocum-endurance.qmd) page is read from
this file. **Adding a sensor is one row.** You do not need the spreadsheet, and you do not need
to run anything: edit the file on GitHub, commit, and the site rebuild picks it up.

```csv
name,ah_per_day,kind,default,source,note
Nortek AD2CP,3.2,fraction,0,vendor datasheet,Sampling at 1 Hz
```

| column | meaning |
|---|---|
| `name` | what appears next to the control |
| `ah_per_day` | amp-hours per day at full duty. The page works in Ah/day at the workbook's 10.8 V reference, so **watts × 24 ÷ 10.8** |
| `kind` | `fraction` for a 0–1 duty control, `percent` for a 0–100 one |
| `default` | where the control starts when the page opens |
| `source` | where the number came from. Fill this in — a number with no source is not usable |
| `note` | optional; shown as a tooltip on the sensor name, marked with `*` |

Each sensor contributes `ah_per_day × duty` to the total daily load. That total is added to the
glider-and-standard-sensor load the workbook's own power model produces, and endurance is battery
capacity divided by the sum.

### Why this is not in the spreadsheet

The Slocum Endurance Tool hardcodes its five external loads inside a single formula:

```
K20 = (K43/100*11.2) + (F50*1.6) + (F51*11.2) + (F52*1.6) + (F53*6.4) + K19
```

Adding a sensor there means editing the workbook, re-extracting the model and rebuilding the page —
and the workbook is not in this repository. Moving those terms into this file makes the payload
editable by anyone with repository access, while `K19` (the 736-formula component power model) is
still the workbook's, untouched.

`code/check_extra_sensors.js` proves the swap changed nothing: it drives 500 random mission
configurations through both the workbook's `K20` formula and this file, and the two agree exactly.
It also reports any row whose `ah_per_day` no longer matches the workbook's coefficient, so a
deliberate re-costing is visible rather than silent.

### Known open question

`JASCO OceanObserver` carries the workbook's **generic hydrophone** figure of 1.6 Ah/day. The
Rodeo 2026 analysis measured capex987 — the OceanObserver glider — at 5.1 W against about 2.2 W for
the rest of the fleet, which implies nearer **6.4 Ah/day**. On the page's default configuration that
is the difference between 75 and 45 days. The number has been left as the workbook's pending a
decision.

## `endurance-model.json`

Generated by `code/extract_endurance_model.py` from `output/Slocum Endurance Tool.xlsx`: the
workbook's own formulas and constants for the endurance chain, plus the values Excel last stored,
which `code/check_endurance_model.js` uses as a regression oracle. Do not edit by hand. The
workbook is gitignored, so regenerating it needs a local copy.
